Door 10 · How to work

Go stand there.

The organization is a bigger variable than the algorithm. Every correction worth making was found by walking the dock.

What it looks like on your floor

Two buildings with the same blueprint and the same equipment. One scans every package off the lane; the other switched scanning off because the rate is four times higher without it, and now that building is invisible to the system meant to staff it. A third trains its stagers to load straight into the trailer, so the system sees one stager in six. A fourth has containers with holes cut in the side because that is what they had. None of this is in any query. All of it was found by standing next to the lane.

Why it is true

Every site does it differently, for reasons that are locally rational every time. Two internal groups want opposite things from the same switch, one for quality and one for cost. A vendor's equipment changes how fast a mode can be flipped. A drop of a few feet breaks big boxes, so a site stops using a mode the model assumes. The model you built is a model of one building. The scaling problem is never compute. It is that the world is not a data-quality issue to be cleaned up. You learn the difference by going.

Monday

  1. Pick the site where your numbers look strangest. Go there. Stand at the lane the system says is in trouble and count.
  2. Ask the floor lead what they do when the light comes on. Write down every answer that is not in your model.
  3. Bring one photo back per thing the model got wrong, and change the model before you change the site.

The rule, and why

No network rollout without a site visit, and no site visit without a list of what the model believes.

A model is a set of claims about a floor. The only way to test a claim about a floor is to look at the floor.

The trap

A site visit is one site. The temptation after a visit is to encode what you saw as the rule. Write it down as a hypothesis, then check it against the next building, which will have done it differently.
